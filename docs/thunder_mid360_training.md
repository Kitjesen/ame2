# Thunder V4 MID-360 接入 AME-2 训练

2026-09-22。入口为 `scripts/train_thunder_mid360.py`，复用服务器 robot_lab 的 `PoseRoughV4` 机器人、动作管理器和奖励。学生使用 AME-2 网络结构，但指令为 Thunder 原有的 `(vx, vy, yaw_rate)`，不是原论文的目标位置指令。当前工作验证接入，不宣称已训练出可用行走策略。

## 输入与控制契约

每环境以 10 Hz 推进 MID-360 pattern，每帧 20,000 条射线；控制周期沿用 Thunder 的 0.02 s。雷达每 5 个控制步更新，期间按当前位姿裁剪历史地图，不反复融合旧扫描。不预先采样成 1,024 点。

每帧分别统计：射线数、排除自身后的有效返回数、自身遮挡的射线数、进入地图的有效点数、占用格数。局部图为 40×48＝1,920 格；多个点可以进入同一格，因此点数不等于格数。自身遮挡包含发生在测距下限以内的遮挡，不将其伪装成有效传感器回波。

学生数据流：

```text
MID-360 pattern + 场景/机身射线查询
  → 最近回波与自身遮挡掩码
  → XYZ 恢复米制 + 全姿态外参变换
  → 同格最高点 + 真实观测标记
  → 冻结 MappingNet
  → 带来源和时间的历史融合
  → [x, y, z, variance] 地图 + 本体历史 + 速度指令
  → AME-2 学生 → Thunder 原动作管理器
```

环境和自身几何分别查询同一组射线，近处的自身命中遮挡远处环境；不是删掉自身点之后再把后方墙面当作可见。机身遮挡采用各 link 的 `visuals` 表面网格，不采用用于刚体接触的粗碰撞盒；物理碰撞配置保持原任务设置。模型中的发射器外壳 `base_link/visuals/lidar1_Link` 包围当前射线原点，因此只将该外壳从自身查询中排除。机身、腿、相机和后雷达仍参与遮挡。这不替代光学原点和轴向的实机标定。

需要配套 OmniPerception 的实例网格遍历及 `mesh_exclude_paths` 修改。原版不遍历 USD instance proxy 时，完整 Thunder 模型无法装入射线几何。

## 学生与 Critic 的边界

| 输入 | 学生 | Critic |
| --- | --- | --- |
| 雷达生成的四通道地图 | 是 | 否 |
| 20 步本体历史 | 是 | 只用当前本体状态 |
| 三维速度指令 | 是 | 是 |
| 地形真值三通道 xyz 地图 | 否 | 是 |
| 仿真基座线速度、全机身接触 | 否 | 是 |

单步历史 54 维：角速度 3 + 重力方向 3 + 关节位置 16 + 关节速度 16 + 已执行动作 16。轮子转角清零，保留轮速，避免无界旋转相位成为姿态输入。关节顺序从现有 Thunder 配置解析并与动作管理器核对；动作仍是 12 个腿关节位置偏移加 4 个轮速。位置/速度缩放和执行器参数由已有任务负责。

Critic 的接触维数来自实际加载的接触传感器；不套用 ANYmal 的 13-link 假设，也不套用它的关节左右镜像。学生接口不传入旧任务的特权观察字典。单测用 NaN 替换全部 Critic 输入，验证学生输出不受影响。

## 运行

在现有 thunder2 环境和已修复的 OmniPerception 上运行，不新增依赖：

```bash
cd /home/bsrl/ame2-mid360-codex
export PYTHONPATH="$PWD:/home/bsrl/omni-test-codex/LidarSensor"
CUDA_VISIBLE_DEVICES=7 python -u scripts/train_thunder_mid360.py \
  --headless --device cuda:0 --num-envs 4 --iterations 2 --terrain plane \
  --mapping-checkpoint artifacts/mid360_validation/mapping_smoke.pt \
  --output artifacts/thunder_mid360_plane
```

`--terrain rough` 使用现有 Thunder 起伏/台阶地形。`--resume` 恢复该新入口生成的 PPO 检查点，不能直接加载旧 ANYmal 或其他 Thunder 网络结构的权重。建图检查点必须与扫描外参、范围、频率和格网一致。

上面的 `mapping_smoke.pt` 是旧夹具实验权重，只用于接入验证。[后续监督建图实验](mid360_mapping_training.md)已经使用不同地形块进行训练和评价，仍暴露前方盲区与补全误差。正式长训之前需要解决这些问题并完成误差/方差校准，再选择教师蒸馏或直接非对称 PPO 路线；当前入口尚无教师动作蒸馏。

## 验证边界

本地相关测试共 41 项通过（原有 38 项，加 3 项训练输入测试）。覆盖点数口径、自身过滤、重复扫描、环境隔离、部分重置、54 维历史、16 维动作、学生无特权输入以及地图编码器梯度。

GPU 7 / RTX 3090 上，平地和起伏/台阶任务各运行 4 环境、2 轮 PPO、每轮 24 个控制步；每环境取得 10 帧扫描。另触发一个环境的真实超时重置，验证其旧历史被清空。以下是每环境每帧均值，不是实机采样统计：

| 数量 | 平地 | 起伏/台阶任务 |
| --- | ---: | ---: |
| 射线数 | 20,000 | 20,000 |
| 排除自身后的有效环境回波 | 10,210 | 9,242 |
| 被机身遮挡的射线 | 3,271 | 3,609 |
| 落入局部地图的点 | 7,123 | 6,514 |
| 当前帧占用格数 / 1,920 | 865 | 716 |

两组均验证有限 PPO 损失和梯度、地图编码器权重更新、MappingNet 冻结、学生不读取 Critic 真值、检查点保存恢复和局部重置。完整结果：[平地](thunder_mid360_plane_20260922.json)、[起伏/台阶](thunder_mid360_rough_20260922.json)。短时起伏任务运行不等于已完成上下台阶能力评估。

退出状态另行记录：起伏任务正常退出（0）；平地任务在结果和检查点验证保存后，模拟器关闭阶段超时，由外部 timeout 结束（124）。独立几何回归同样是断言全通过、关闭阶段超时（124）。GPU 7 最后恢复至 14 MiB、无计算进程。关闭问题仍需处理，不能把断言通过说成所有运行正常退出。

整机实验需额外检查：真实环境返回必须进入地图、有限 PPO 损失/梯度、地图编码器权重更新、建图网络冻结、检查点保存恢复。仅有 PPO 损失下降不证明雷达地图可用，也不证明学会行走。

当前使用仿真位姿与每帧一个姿态，未模拟帧内运动畸变、真实里程计漂移或真实测量噪声。实验建图权重不保证台阶边缘质量；前雷达扫描轴和实际地面可观测性仍需独立标定。
